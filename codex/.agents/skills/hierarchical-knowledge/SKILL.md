# Hierarchical knowledge

Preserve the project's working format. Group by likely use:

- Combine short context usually needed together; avoid a node per label.
- Make independent documents separately retrievable: three substantial speeches usually mean three nodes; a short brief can stay one.
- Nodes are reading units; files may hold several. Keep shared ancestors brief and detail optional. Give each fact one owner; link elsewhere.

Write compact, self-contained notes. Remove filler, repetition, and chat narration. Preserve decision status, conditions, units, and rationale that changes interpretation. Prefer bullets or small tables when clearer. Keep transcripts and quoted source material verbatim unless editing or summarizing them is requested.

Split when a task can omit meaningful content, not to meet size quotas.

Load only as needed: [format](references/format.md) for syntax; [audit](references/audit.md) for usage measurement; [complete reads](references/complete-reads.md) for full or truncated reads.

Validate affected knowledge; fix introduced failures and rerun affected checks. Report unresolved failures. Review authored changes, not unchanged tooling dumps.

Reader: Python 3, standard library only. Optional audit: macOS/Linux.
